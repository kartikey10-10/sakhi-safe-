# Sakhi Safe

React Native CLI / TypeScript Android application and GitHub Pages APK download site. The app does not use Expo Go and the installed APK runs independently.

## Stack

- React Native 0.81.4, React 19.1, TypeScript.
- React Navigation bottom tabs, AsyncStorage local persistence, Android Keychain credential storage.
- Android Gradle Plugin 8.9.2, Gradle 8.13, JDK 17, Android SDK 36.
- `react-native-contacts` for on-demand Android contact import and `@react-native-community/geolocation` for one-time SOS location.
- Static Vite website with bundled `qrcode` generator, deployed with GitHub Pages Actions.

## Project map

- `App.tsx`: app navigation and screen composition.
- `src/storage/store.ts`: local persistence helpers.
- `src/services/contacts.ts`, `src/services/sos.ts`: permission-gated native actions.
- `src/services/demo.ts`: future backend/device service boundaries.
- `src/types/`, `src/utils/`: shared models and validation.
- `android/`: native manifest, Kotlin entry points, Gradle configuration and wrapper bootstrap.
- `.github/workflows/android.yml`: validation, APK build/artifact, tagged release.
- `.github/workflows/deploy-pages.yml`: static site build and GitHub Pages deployment.
- `website/`: public download page and QR code generation.

## Local development

Install Node.js 20+, JDK 17, Android command-line tools, SDK platform/build-tools 36, and set `ANDROID_HOME` (or `ANDROID_SDK_ROOT`) and `JAVA_HOME`. The checked-in `android/gradlew` and `gradlew.bat` bootstrap Gradle 8.13 into the Gradle user cache; the first use needs access to `services.gradle.org`.

```powershell
npm install
npm run typecheck
npm test -- --ci
```

The project currently has no `package-lock.json`: the source workspace was supplied without one, and the registry is unreachable in the implementation environment. The Android workflow therefore uses `npm install` with direct dependencies pinned in `package.json`. Generate and commit a lockfile when registry access is available; then switch CI to `npm ci` and enable setup-node's npm cache.

## Android debug build

```powershell
cd android
.\gradlew.bat :app:assembleDebug
```

On Linux/macOS:

```sh
cd android
./gradlew :app:assembleDebug
```

Output is `android/app/build/outputs/apk/debug/app-debug.apk`. The GitHub Actions artifact is named `SakhiSafe.apk` and is a debug-key-signed development build, suitable for local installation/testing and not a Play Store release.

### Wrapper details

Gradle 8.13 is pinned in `android/gradle/wrapper/gradle-wrapper.properties`; local bootstrap scripts download that distribution. The standard Gradle wrapper JAR was not present in the supplied project and could not be generated on this machine because Java/Gradle and network access are unavailable. The Android workflow installs Gradle 8.13 and generates the canonical wrapper files during the runner job before invoking it. Run `gradle wrapper --gradle-version 8.13 --distribution-type bin` from `android/` on a machine with Gradle installed to generate and commit the standard wrapper JAR and scripts.

## GitHub Actions and Releases

The Android workflow runs on pushes to `main`, pull requests, version tags `v*`, and manual dispatch. It runs TypeScript checks and unit tests, installs JDK/Android SDK, builds the APK, verifies the file, and uploads an Actions artifact.

Create a tag such as `v1.0.0` to trigger a release. If signing secrets are absent, the release is built with the debug key and published as a prerelease. To create a signed release, configure these repository Actions secrets:

- `ANDROID_SIGNING_KEY_BASE64`: base64-encoded release keystore.
- `ANDROID_SIGNING_STORE_PASSWORD`
- `ANDROID_SIGNING_KEY_ALIAS`
- `ANDROID_SIGNING_KEY_PASSWORD`

The workflow never stores the keystore in Git. Signed tag releases are published as non-prereleases with `SakhiSafe.apk` and a SHA-256 checksum. The stable URL is `https://github.com/OWNER/REPOSITORY/releases/latest/download/SakhiSafe.apk`, where OWNER/REPOSITORY are supplied by GitHub at deployment time.

## GitHub Pages website

See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). The site workflow gets the repository name from GitHub Actions, writes it to a generated `site-config.json`, builds the website, and deploys the Pages artifact. The QR code is generated by the bundled `qrcode` package and points to the stable latest-release APK URL. Before a release exists, the link naturally has no APK to serve.

## Backend configuration and boundaries

Copy `.env.example` to a local `.env` only when a backend is implemented. The current frontend does not load or use these placeholders. A future service should supply `API_BASE_URL` or the Supabase URL and anonymous key; never add service-role keys, signing material, or private tokens to frontend variables. GitHub Pages is static hosting, not a backend.

The current app works locally without backend credentials. Local profile/contact/learning/scenario/settings data are stored on-device. Registration is local device authentication, not a cloud account. The password is stored using Android secure credentials. A forgotten local login cannot be recovered remotely. Contacts import and one-time location request ask for permissions only when invoked. SMS opens the user's SMS composer and the app cannot confirm send status. The 112 action opens the phone dialer. No police dispatch, cloud alert, push notification, community moderation, or companion hardware integration is connected. Device status is shown only as unavailable; no electrical-defense controls exist.

## Tests and current limitations

Automated CI checks TypeScript, runs validation unit tests, and compiles the Android app. There is no emulator or physical-phone test in this workspace. Permission denial, SMS composition, dialer handoff, and contact picker need device verification after CI produces an APK. The website fetches public GitHub release metadata at runtime and falls back to the stable URL if GitHub's API is unavailable. The supplied workspace had no remote repository, Git executable, Gradle wrapper JAR, or Android toolchain, so APK generation and website publication have not been verified here.
